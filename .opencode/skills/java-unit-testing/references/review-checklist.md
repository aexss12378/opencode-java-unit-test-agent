# 測試審查清單

## 規格對齊

- 每個測試都能對應一個已核准的測試意圖編號。
- 正式測試與行為刻畫測試有明確區分。
- 預期值來自核准規格或已標示的現況觀察，不是從實作重算相同邏輯。
- 沒有把缺乏來源的推測寫成正式斷言。

## 斷言品質

- 斷言檢查具體值、狀態改變、例外型別與必要訊息，或精確互動。
- 不單獨使用 `assertNotNull`、寬鬆範圍或只確認「沒有丟例外」。
- 不以同一套正式程式邏輯計算預期值。
- 測試在對應行為被破壞時確實會失敗。

## 隔離與穩定性

- 不依賴網路、真實資料庫、系統時間、時區、亂數種子或測試順序。
- 不使用 `Thread.sleep()` 或沒有上限的等待。
- 測試不共享可變全域狀態，資源在測試後確實釋放。
- 參數化測試的案例名稱能辨識失敗輸入。

## 模擬品質

- 只模擬受測物件之外、不可控制的協作者。
- 不模擬資料類別、集合、值物件或受測物件本身。
- 互動驗證是規格的一部分，而不是為了增加驗證數量。
- 沒有過度指定與測試行為無關的呼叫順序或內部細節。

## 範圍與回歸

- 所有新增版本控制差異都位於核准的 `src/test/**`。
- 沒有修改、格式化或還原使用者既有變更。
- 新測試、受影響模組測試及基準比較都有實際輸出。
- JaCoCo 與 PIT 只在專案已具備能力時執行，且範圍限於目標類別和測試。
